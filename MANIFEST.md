# File 17 — v2.1.0 release manifest and source-of-truth boundary

The installable package is generated by `sabri-network/tools/package.sh`: it stages the complete `sabri-network/` runtime tree (excluding tests, tools and build outputs), emits a per-file `sabri-network/MANIFEST.sha256`, then builds a deterministic ZIP and an external matching `17-sabri-network-and-messages-2.1.0.manifest.sha256`. The full quality gate repeats the build and verifies reproducibility.

**Repository-root `CHECKSUMS.sha256` is historical; it is not the current v2.1.0 release manifest.** It predates File-17 additions and cannot establish current package or deployment parity. Do not use stale static inventories as release evidence. Only the generated SHA-256 manifest attached to the **same exact GitHub Actions commit** supports that package.

Installable payload: runtime PHP, templates, CSS, JS, app assets and plugin guides. Excluded from the WordPress ZIP: root reports, `.github/`, `sabri-network/tests/`, `sabri-network/tools/`, and `sabri-network/build/`.

A successful source package is **not** proof of installation, migration, external providers or production behavior. Compare the deployed artifact to the exact accepted package during Live Reality Freeze. See `V12.3-FILE17-RECONCILIATION.md`.
